# TERANGA-05B — SEO implementation

Audience: engineers maintaining the site. Baseline: `docs/TERANGA-05B-baseline-audit.md`. Keywords: `docs/TERANGA-05B-search-strategy.md`. Claims: `docs/TERANGA-05B-proof-register.md`.

No framework, dependency or third-party script was added. Everything is generated by `site/build.mjs`, as before.

## 1. Crawling and canonical URLs

| Change | Where | Effect |
|---|---|---|
| `"trailingSlash": false` | `vercel.json` | `/services/` → 308 `/services` (the canonical); `/fr/` → `/fr` |
| Host redirect `teranga-technologies.vercel.app/:path*` → `https://teranga-tech.com/:path*` (308) | `vercel.json` `redirects[0]` | The project's default `.vercel.app` production alias no longer serves a duplicate site. It matches that exact host only; preview hosts are unaffected (verified on the preview) |
| No change | robots.txt, sitemap structure, canonical / hreflang | Already correct; now covered by more tests |
| Owner action | `www.teranga-tech.com` | Add it in Vercel → Domains as a **308** redirect to `teranga-tech.com` (today Vercel's default 307 applies) |

Previews keep Vercel's own `X-Robots-Tag: noindex` and login. The site sets no `X-Robots-Tag` itself, and a test fails if one is added to `vercel.json`.

## 2. Metadata

- **Titles and descriptions:** rewritten for Home, Services, AI Engineering, Work and About in both languages, following the keyword map. Contact and Privacy are unchanged. Still unique and length-bounded (test).
- **`og:title`** for Home follows the new positioning. Other Open Graph and Twitter tags already derive from the page title, description and canonical.
- **Verification tags:** `site/config.mjs` → `SEARCH_VERIFICATION.google` / `.bing`, empty by default. When set, the generator adds `google-site-verification` / `msvalidate.01` meta tags to indexable pages, escaped. DNS verification is preferred and needs no code.
- **Favicon:** `favicon.ico` (16/32/48 px, generated from `assets/brand/teranga-mark.svg`) plus the SVG icon. Search results show a favicon, and browsers stop requesting a missing file.

## 3. Structured data

One JSON-LD `@graph` per indexable page (`site/layout.mjs` → `structuredData`):

| Node | Pages | Content |
|---|---|---|
| `Organization` `https://teranga-tech.com/#organization` | All | Name, URL, logo, image, description (home description in the page language), email, telephone, address (Dakar, SN), languages, a sales `ContactPoint` |
| `WebSite` `…/#website` | All | Name, URL, languages, publisher → Organization |
| `WebPage` / `AboutPage` / `ContactPage` `<canonical>#webpage` | All | Name = `<title>`, description = meta description, URL = canonical, `inLanguage`, `isPartOf` → WebSite, `about` → Organization |
| `Service` ×6 `<services URL>#<section id>` | Services | Name = the visible section name (now inside the `<h2>`), description = the section headline, `provider` → Organization |

**Removed:**
- the home-only `ProfessionalService` (a LocalBusiness type, which implies a customer-facing location);
- `streetAddress: 'Ngor Almadies'`, a neighbourhood;
- `areaServed` Africa / Europe / North America, which the pages don't state.

**Deliberately not added:**

| Markup | Why |
|---|---|
| `BreadcrumbList` | The site has two levels and no visible breadcrumb trail. The markup would describe navigation that isn't on the page |
| `FAQPage` | The contact page has a real FAQ, but Google shows FAQ rich results only for well-known government and health sites (since 2023), so the markup would add maintenance without visible benefit. Revisit only if that changes |
| `sameAs` | Requires verified profiles (owner checklist) |
| Ratings, reviews, founders, awards | None documented |

**Validation:**
- `tests/site.test.js` parses every block;
- checks that every `@id` reference resolves;
- checks that email and phone are visible on the page;
- checks that names and URLs match the page's own title and canonical;
- checks that every Service name is a visible heading;
- forbids the excluded types and properties.

On the preview, the graph was also checked for syntax and required properties (release report). Rich results are not promised: structured data helps search engines understand the page and doesn't guarantee any display.
